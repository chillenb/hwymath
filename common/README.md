# Shared code

Code used by more than one function. Families keep code shared only among themselves in their first member's
directory (the log family in `functions/log/`, sin/cos/tan in `functions/sin/`); anything used across
families lives here.

| path | contents |
|---|---|
| `include/hwymath/test_util.h` | bit casts, random inputs, test helpers (C and C++) |
| `include/hwymath/accuracy.h` | ulp errors against a `long double` reference, statistics, result hashes (FNV-1a), benchmark timing |
| `include/hwymath/hwy/avx512_emul-inl.h` | Highway versions of AVX-512 instructions: `vrcp14pd`/`vrsqrt14pd` (exact emulation, or the instruction on AVX-512 targets), `vgetexppd` (positive normal inputs), 16-entry `vpermt2pd` lookups |

| `include/hwymath/rcp14_ref.h` | scalar reference of `vrcp14pd` over its whole domain (denormals, special values), C and C++ |

## vrcp14pd and vrsqrt14pd

The SDM only bounds their relative error (2⁻¹⁴), so they are often taken to be
implementation-defined. But Intel publishes a bit-exact reference ("Reference Implementations for IA
Approximation Instructions VRCP14, VRSQRT14, VRCP28, VRSQRT28, and VEXP2", `RECIP14.c`, BSD-3-Clause),
which Intel SDE follows; `tests/approx14/test_approx14` confirms it against the instructions (under SDE here) for every
mantissa prefix that matters. For a mantissa in [1, 2) (rcp14) or [1, 4) (rsqrt14) the reference evaluates a
linear function on one of 64 segments with integer coefficients,
r = a[i] − 256·b[i]·(xt − y[i]), where y[i] is the centre of segment i and xt is x truncated to 17 (rsqrt:
16) significant bits, and truncates r to 17 bits (everything is exact in double precision). The results
depend on x only through its exponent and top 16 (rcp14) or 15 (rsqrt14, plus the exponent parity) mantissa
bits.

The Highway emulation (`include/hwymath/hwy/avx512_emul-inl.h`; first written for asinh, acosh and atanh):

- the 64-entry coefficient tables would need gathers, so the coefficients are computed:
  b = 2·⌊512/y²⌋ + 1 and d = 2·⌊K/y^1.5⌋ + 1 (K = 512 on [1, 2), 1024 on [2, 4)) hold for every segment;
  a = ⌊2¹⁸/y⌋ + ra[i] and c = ⌊2¹⁹/√y + α·y^−2.5 − 2⌋ + rc[i] (α = 20.5 / 46.5) with corrections
  ra, rc ∈ 0..15 stored as 4-bit fields in four 64-bit words (selected with two `IfThenElse` on the index
  bits, extracted with a variable shift). One division (rcp14), a square root and a division (rsqrt14).
  `tools/gen_approx14.py` simulates the vector code's double operations (FMAs rounded once via exact
  rationals) to derive the corrections and checks the b/d formulas;
- y[i] and xt are built from the mantissa bits; xt − y is exact; r = NegMulAdd(256·b, xt − y, a) is exact
  (exactly representable, so the fused operation does not round); the truncation, the exponent
  (1023 − e for rcp14, −⌊(e − 1023)/2⌋ for rsqrt14) and the special cases (powers of two / of four, ±0, +inf,
  NaN) are integer operations.

Domains: `Rcp14` for positive normal x with a normal reciprocal; `Rsqrt14` for ±0, +inf, NaN and positive
normal x. Other inputs give unspecified values; every caller only uses lanes in these domains (the others go
to the scalar callout). tan needs `vrcp14pd` for any sign and for denormals: `functions/tan/hwy/rcp14_hwy-inl.h`
is a full-domain version, checked against `include/hwymath/rcp14_ref.h`. The log family, pow and cbrt only use
the reciprocal rounded to 4 or 5 bits (`vrndscalepd(vrcp14pd(m))`), which they compute from thresholds (log, cbrt) or a division with corrections near the switch points (pow).

On AVX-512 targets all of them use the instruction itself, which is cheaper. Intel's CPUs (checked on Xeon
6975P-C, Xeon Platinum 8573C) and AMD Zen 4 and Zen 5 (EPYC 9V74, 9V45) follow the reference exactly, as Intel
SDE does.

**Verification.** `make common-test` (part of `make test` and `make avx512-test`) runs `test_approx14`: the
scalar reference (`tests/approx14/approx14_ref.h`) against the instructions when AVX-512 is available (or
under SDE), and every Highway target against the reference, for all 2¹⁶ mantissa prefixes with several low-bit
patterns at 14 exponents. On AVX-512 targets that compares the instruction with the reference; the emulation
itself is then covered by the AVX2 target on the same machine.

The coefficient tables come from Intel's `recip14.c` (Copyright (c) 2015 Intel Corporation, BSD-3-Clause;
the notice is in [LICENSE](../LICENSE)).

## xcheck.sh

`common/tools/xcheck.sh FUNCTION HWY_PREFIX CROSS_PREFIX [N]` builds the function's Highway version and test
driver (`functions/<f>/tests/hwy_xcheck.cc` by default) statically for x86-64 (`-march=native`) and for
AArch64 NEON, SVE and SVE2 with the conda-forge cross compiler, runs the AArch64 binaries under QEMU (SVE at
128, 256, 512 and 2048 bits by default, so every table-lookup code path runs: 2, 4, 8 and 32 lanes), and
compares the inputs and results bit for bit with the x86-64 run. Sources, flags and vector lengths can be
changed through `XC_*` environment variables (see the script); `function.mk` sets them.
