# acosh (double precision)

Source studied: [`svml_z0_acosh_d_ha.s`](https://github.com/numpy/SVML/blob/9a43e744b15006d63e8d1b57626dfbe6b984f5ee/linux/avx512/svml_z0_acosh_d_ha.s)
(AVX-512, high accuracy). Accuracy and speed: [Performance.md](Performance.md). The algorithm is asinh's
([../asinh/README.md](../asinh/README.md)) with x² − 1 in place of x² + 1, and the Highway version uses the
AVX-512 emulations described there (`functions/asinh/hwy/avx512_emul-inl.h`).

| path | contents |
|---|---|
| `svml/` | bit-identical C/AVX-512 translation of the assembly, with its constants (`svml_acosh_d_ha_constants.inc`, generated by `tools/gen_svml_constants.py`, which runs asinh's generator: same data layout) |
| `hwy/hwy_acosh.cc` | portable Google Highway version, bit-identical to Intel's code on every target with FMA |
| `tests/` | tests, comparison implementations (Intel SVML, SLEEF), test inputs |
| `acosh_d.h` | declarations of the C kernels |
| `function.mk` | build rules and the `acosh-*` make targets |

## Algorithm

- Y = x² − 1 = Yh + Yl exactly (from the FMA error of x² and the rounding error of x² − 1);
  R0 = `vrsqrt14pd`(Yh), and S = √Y ≈ Sh + Sl + Sh·Eh·poly(Eh) as in asinh (Sh = Yh·R0, Eh = 1 − R0²·Y).
- Yh < 2⁻¹¹ (`kSmallX`, i.e. x < ~1.00024): acosh(x) = asinh(S) = S + S·Y·(C1 + C2·Y + C3·Y²), with S
  as a double-double (same polynomial as asinh's small-input path).
- otherwise acosh(x) = log(x + S), with Xin = x + S as a double-double and the log of asinh
  (`vrcp14pd` rounded to 1+4 mantissa bits, `vgetexppd`, 16-entry tables with `vpermt2pd`, degree-8
  polynomial); for x ≥ 2⁵¹¹ (x² overflows) Xin = x/8 and 4·ln2 is added. There Yh is a NaN (inf − inf in
  the exact split), which the `NLT_UQ` compare sends to the log path.
- Lanes with x ≤ 1, x > DBL_MAX or NaN call the scalar routine: NaN → x·x, +inf → +inf, 1 → +0 (return code 0),
  everything else (x < 1, −inf) → NaN with the invalid flag (return code 1). x = 1 must take the callout:
  in the vector path Yh = 0, `vrsqrt14pd`(0) = +inf and Sh = 0·inf would give a NaN.

The scalar routine computes the NaN as +inf·0 (the x86 default NaN, 0xfff8000000000000); the C translation
raises the flag the same way but stores that bit pattern explicitly, so the callout also returns it on
AArch64, whose default NaN is positive.

## The C translation and the Highway version

As for asinh: `svml/svml_acosh_d_ha.c` (`svml_acosh8_ha`, `svml_acosh_ha_array`, `svml_dacosh_ha_cout_rare`)
is bit-identical to `__svml_acosh8_ha` (`test_acosh8`) and has the same arithmetic instruction mix
(`make acosh-insns`). `hwy/hwy_acosh.cc` performs the same operations in the same order with the exact
emulations of `vrsqrt14pd`, `vrcp14pd`, `vgetexppd` and `vpermt2pd`; it is **bit-identical to Intel's code**
on every target with FMA (AVX2 and AVX3* under Intel SDE against the translation; NEON, SVE at
128–2048 bits and SVE2 under QEMU against x86-64 with `make acosh-xcheck`). Targets without FMA use
`std::acosh`. Deviations: none in the results; the Highway version may raise floating-point exception flags
that Intel's `{sae}` code suppresses.

## Tests (`make acosh-test`, `make acosh-avx512-test`)

| test | compares with | result |
|---|---|---|
| `test_rare` | Intel's scalar `__svml_dacosh_ha_cout_rare_internal`: results, return codes, FP exception flags | 20,006,200 inputs, 0 mismatches |
| `test_acosh8` | Intel's `__svml_acosh8_ha`: all 8 lanes bit-exact | 20,006,200 inputs, 0 mismatches (Intel SDE, `-spr`); needs AVX-512 (else skipped) |
| `hwy_test` | every Highway target: max error < 1 ulp vs `acoshl`, special results (NaN below 1, +0 at 1, +inf), agreement between targets, bit-identity with the C translation when AVX-512 is available | all checks pass (SDE: AVX3, AVX3_DL, AVX3_SPR, AVX2 bit-identical to the translation) |
| `make acosh-insns` | arithmetic instruction mix of the compiled vector path vs the assembly | identical |

The emulated instructions themselves are tested by asinh's `test_approx14`.

Inputs (`tests/inputs.h`): ±0, ±1, ±inf, NaNs, denormals, ±DBL_MAX, 1 + k³ ulps for k < 1000; ±100 ulps
around 1, √(1 + 2⁻¹¹), 2⁵¹¹, DBL_MAX, the overflow of x², 2²⁶ and 2²⁷ (x² − 1 rounds to x²); inputs for
which x + √(x² − 1) is next to the rounding midpoints of the 5-bit reciprocal and the table boundaries; random
values uniform in [1, 1.002], [0.5, 4], [1, 1000], log-uniform positive over the whole range, and random bit
patterns. All are built with IEEE operations only (no libm), so they are identical on every architecture.
