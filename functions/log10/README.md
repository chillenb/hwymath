# log10 (double precision)

Source studied: [`svml_z0_log10_d_ha.s`](https://github.com/numpy/SVML/blob/9a43e744b15006d63e8d1b57626dfbe6b984f5ee/linux/avx512/svml_z0_log10_d_ha.s)
(AVX-512, high accuracy). Accuracy and speed: [Performance.md](Performance.md). Part of the log family: the
emulation helpers, the `vrcp14pd` analysis, the constant generator and the test driver live in
[functions/log](../log/README.md); this directory has what is specific to log10.

| directory | contents |
|---|---|
| `svml/` | bit-identical C/AVX-512 translation of the assembly, with its constants (`svml_log10_d_ha_constants.inc`, generated by `functions/log/tools/gen_svml_constants.py log10`) |
| `hwy/` | Google Highway version (`hwy_log10.cc`, constants `hwy_log10_constants.inc` generated with `--cxx`) |
| `tests/` | `inputs.h`, `test_rare.c`, `test_log108.c`, `hwy_test.cc` / `hwy_xcheck.cc` (drivers shared with log) |
| `log10_d.h` | declarations of the C translation |
| `function.mk` | build rules and the `log10-*` make targets |

## Algorithm

Vector path: like [log](../log/README.md) (x = 2^E·m, rcp = `vrndscalepd(vrcp14pd(m))` = k/32, exact
R = rcp·m − 1, E + 1 and a −log10(2·rcp) entry when rcp < 0.75), with log10 tables Th + Tl = −log10(rcp)
and log10(1 + R) = c1h·R + R·(c1l + c2 R + … + c9 R⁸), c1h + c1l = 1/ln 10:
KT = E·L2H + Th (exact: L2H = log10(2) rounded to 37 bits), H = KT + c1h·R (FMA), (c1h·R)_h = H − KT,
(c1h·R)_l = c1h·R − (c1h·R)_h (FMA), result = H + (R·p + ((E·L2L + Tl) + (c1h·R)_l)). Lanes with x = ±0,
±inf or x < 0 (`vfpclasspd` 0x5e) are recomputed by the scalar routine; NaN and denormal inputs stay in the
vector path.

The scalar callout `__svml_dlog10_ha_cout_rare_internal` has the structure of log's (denormals scaled by 2^60,
|x − 1| ≤ 2^-7.4 by a polynomial in s = 0.43359375·(x − 1), otherwise a 65-entry table whose reciprocals
are pre-multiplied by 0.43359375 ≈ 1/ln 10, degree-8 polynomial, separate scaling of the split reduced
argument). Return codes: 1 (x < 0 or −inf), 2 (±0).

## The C translation

`svml/svml_log10_d_ha.c`: AVX-512 intrinsics with the assembly's constants (hex-float literals), operation order
and rounding modes; `svml_log108_ha()` (AVX-512F/DQ, the only function compiled for AVX-512),
`svml_log10_ha_array()`, and the scalar callout `svml_dlog10_ha_cout_rare()` in plain C without FMA contraction.
Bit-identical to `__svml_log108_ha` (`test_log108`), same instruction mix (`make log10-insns`).

## Highway version (`hwy/hwy_log10.cc`)

The same algorithm written with Google Highway, run-time dispatch; on every target with true FMA it performs
the same floating-point operations in the same order with the same rounding as `__svml_log108_ha`, and its
results are **bit-identical** to Intel's AVX-512 code: verified under Intel SDE for AVX2, AVX3, AVX3_DL,
AVX3_SPR (`-spr`) and AVX10_2 (`-dmr`) against the C translation, and under QEMU for AArch64 NEON, SVE and
SVE2 at 128/256/512/2048-bit vectors against x86-64 (`make log10-xcheck`). Targets without FMA use `std::log10`.

The AVX-512-only operations are emulated exactly by the helpers shared with log (`functions/log/hwy/log_hwy-inl.h`;
details, and the proof that the rounded `vrcp14pd` can be reproduced exactly, in [log's README](../log/README.md)):

| AVX-512 | emulation |
|---|---|
| `vgetmantpd`, `vgetexppd` | integer operations; denormals pre-scaled by 2^52 in a slower variant used only for vectors with a denormal or special lane |
| `vfpclasspd` 0x5e + callout | `!(x >= DBL_MIN && x < inf)` selects the slow variant, then the C callout for `!(x > 0 && x < inf)`; NaN lanes also go to the callout, which returns the same quieted NaN as the vector path |
| masked `vxorpd` | not needed (special lanes are overwritten) |
| `vpermt2pd` (16-entry tables) | `TwoTablesLookupLanes` (one `vpermt2pd` on AVX-512), two/four of them plus selects on 4/2-lane vectors, `TableLookupLanes` on ≥ 16 lanes. No gathers |
| `vrcp14pd` + `vrndscalepd` | exact model: 16 measured thresholds of the rounded reciprocal, a 32-entry `uint32` table and integer operations on the high word of the mantissa |
| masked `vaddpd` (E + 1 if rcp < 0.75) | `MaskedAddOr` |
| `{rn-sae}` | all rounding is round-to-nearest: plain `MulAdd`/`MulSub`/`Add`/`Mul` |

Deviations: none in the results. The vector code may raise FP flags where the `{sae}` assembly does not;
special lanes go through the same C callout, which raises the documented flags. The C callout returns NaNs
with x86's default-NaN sign on every architecture (`copysign(..., -1.0)`, a no-op on x86), so that AArch64
results are identical.

## Tests (`make log10-test`, `make log10-avx512-test`)

| test | compares with | result |
|---|---|---|
| `test_rare` | Intel's scalar `__svml_dlog10_ha_cout_rare_internal`: results, return codes, FP exception flags | 20,029,320 inputs, 0 mismatches |
| `test_log108` | Intel's `__svml_log108_ha`: all 8 lanes bit-exact | 2,029,320 inputs, 0 mismatches (Intel SDE `-spr`); needs AVX-512F/DQ |
| `hwy_test` | every Highway target: error < 1 ulp, special values vs `log10l`, agreement between targets, special lanes bit-identical to the C callout; with AVX-512: every target bit-identical to the C translation | all checks pass (AVX2 natively; AVX2, AVX3, AVX3_DL, AVX3_SPR under SDE) |
| `make log10-insns` | arithmetic instruction mix of the compiled vector path vs the assembly | identical |
| `make log10-xcheck` | Highway on AArch64 NEON/SVE/SVE2 (QEMU) vs x86-64 | bit-identical |

Inputs: the same file as log's (`tests/inputs.h`). The Highway test driver (`functions/log/tests/log_family_test.h`), the comparison implementations
(`functions/log/tests/extras*`, compiled with `-DFN=log10`) and the constant generator
(`functions/log/tools/gen_svml_constants.py log10`) are shared with log. `make log10-hashes` writes
`arch log10 <target> svml n hash` lines (and `C-AVX512` for the translation when the CPU has AVX-512): all equal.
