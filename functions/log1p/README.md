# log1p (double precision)

Source studied: [`svml_z0_log1p_d_ha.s`](https://github.com/numpy/SVML/blob/9a43e744b15006d63e8d1b57626dfbe6b984f5ee/linux/avx512/svml_z0_log1p_d_ha.s)
(AVX-512, high accuracy). Accuracy and speed: [Performance.md](Performance.md). Part of the log family: the
emulation helpers, the `vrcp14pd` analysis, the constant generator and the test driver live in
[functions/log](../log/README.md); this directory has what is specific to log1p.

| directory | contents |
|---|---|
| `svml/` | bit-identical C/AVX-512 translation of the assembly, with its constants (`svml_log1p_d_ha_constants.inc`, generated by `functions/log/tools/gen_svml_constants.py log1p`) |
| `hwy/` | Google Highway version (`hwy_log1p.cc`, constants `hwy_log1p_constants.inc` generated with `--cxx`) |
| `tests/` | `inputs.h`, `test_rare.c`, `test_log1p8.c`, `hwy_test.cc` / `hwy_xcheck.cc` (drivers shared with log) |
| `log1p_d.h` | declarations of the C translation |
| `function.mk` | build rules and the `log1p-*` make targets |

## Algorithm

Vector path: 1 + x is formed as a double-double Xh + Xl with Xh = RN(1 + x) and
Xl = min(1, x) − (Xh − max(1, x)) (exact, `vmaxpd`/`vminpd`), then log(Xh + Xl) as in [log](../log/README.md):
Xh = 2^E·m, rcp = `vrndscalepd(vrcp14pd(m))` = k/32, R = rcp·m − 1 (exact), and the low part enters the
reduced argument as R' = R + rcp·Xl·2^-E (`vscalefpd`), with the rounding error Rl of that addition kept.
Then High = E·L2H + Th, HR = High + R', Rh = HR − High, Rl2 = R' − Rh, and
result = HR + ((R'²·p + Rl2) + (E·L2L + (Tl + Rl))) with the same degree-9 polynomial and tables as log,
finally OR-ed with the sign of x (log1p(−0) = −0). Lanes where Rl2 is NaN (x ≤ −1, ±inf, NaN) are
recomputed by the scalar routine.

The scalar callout `__svml_dlog1p_ha_cout_rare_internal` is SVML's scalar log (same table and polynomials as
log's) applied to x2 = RN(1 + x), with the special cases decided on x2. Return codes: 1 (x < −1 or −inf:
NaN, invalid), 2 (x = −1: −inf, divide-by-zero).

## The C translation

`svml/svml_log1p_d_ha.c`: AVX-512 intrinsics with the assembly's constants (hex-float literals), operation order
and rounding modes; `svml_log1p8_ha()` (AVX-512F, the only function compiled for AVX-512),
`svml_log1p_ha_array()`, and the scalar callout `svml_dlog1p_ha_cout_rare()` in plain C without FMA contraction.
Bit-identical to `__svml_log1p8_ha` (`test_log1p8`), same instruction mix (`make log1p-insns`).

## Highway version (`hwy/hwy_log1p.cc`)

The same algorithm written with Google Highway, run-time dispatch; on every target with true FMA it performs
the same floating-point operations in the same order with the same rounding as `__svml_log1p8_ha`, and its
results are **bit-identical** to Intel's AVX-512 code: verified under Intel SDE for AVX2, AVX3, AVX3_DL,
AVX3_SPR (`-spr`) and AVX10_2 (`-dmr`) against the C translation, and under QEMU for AArch64 NEON, SVE and
SVE2 at 128/256/512/2048-bit vectors against x86-64 (`make log1p-xcheck`). Targets without FMA use `std::log1p`.

On every target except the AVX-512 ones, the AVX-512-only operations are emulated exactly by the helpers shared with log (`functions/log/hwy/log_hwy-inl.h`;
details, and the proof that the rounded `vrcp14pd` can be reproduced exactly, in [log's README](../log/README.md)):

| AVX-512 | emulation |
|---|---|
| `vgetmantpd`, `vgetexppd` (of Xh = 1 + x) | integer operations (Xh ≥ 2^-53 is normal in all lanes that do not take the callout) |
| `vscalefpd` (Xl·2^-E, E ∈ [−53, 1023]) | Xl·2^(60−E) (exact, power of 2 built from the exponent bits) times 2^-60: a single rounding, as `vscalefpd`'s, also when the result is subnormal |
| `vmaxpd`/`vminpd` {sae} | `Max`/`Min` (no NaN in the lanes that matter) |
| `vandpd`/`vorpd` (sign of x) | integer `And`/`Or` on the bits |
| `vcmppd` NEQ_UQ (Rl2 is NaN) + callout | `!(1 + x > 0 && 1 + x < inf)`, the same lanes; then the C callout |
| `vpermt2pd` (16-entry tables) | `TwoTablesLookupLanes` (one `vpermt2pd` on AVX-512), two/four of them plus selects on 4/2-lane vectors, `TableLookupLanes` on ≥ 16 lanes. No gathers |
| `vrcp14pd` + `vrndscalepd` | exact model: 16 measured thresholds of the rounded reciprocal, a 32-entry `uint32` table and integer operations on the high word of the mantissa |
| masked `vaddpd` (E + 1 if rcp < 0.75) | `MaskedAddOr` |
| `{rn-sae}` | all rounding is round-to-nearest: plain `MulAdd`/`MulSub`/`Add`/`Mul` |

On the AVX-512 targets (`HWYMATH_NATIVE_AVX512`) Intel's instructions are used instead (see
[log's README](../log/README.md)): `vgetexppd`/`vgetmantpd` of Xh, `vrcp14pd` + `vrndscalepd`, the unmasked
`vpsrlq $48` index into `vpermt2pd`, `vscalefpd` of Xl by −E (a `vxorpd` on E, as in Intel's code), and
`vfpclasspd $0xdf` on Xh = 1 + x for the special lanes (one instruction, like Intel's `vcmppd` on Rl2, and
the same lanes). AVX3 loop: 43 vector/mask instructions besides loads, stores and register moves (57 with the
emulations), the same as Intel's main path (43, counting `kmovw` like our `kortestb`).

Deviations: none in the results. The vector code may raise FP flags where the `{sae}` assembly does not;
special lanes go through the same C callout, which raises the documented flags. The C callout returns NaNs
with x86's default-NaN sign on every architecture (`copysign(..., -1.0)`, a no-op on x86), so that AArch64
results are identical.

## Tests (`make log1p-test`, `make log1p-avx512-test`)

| test | compares with | result |
|---|---|---|
| `test_rare` | Intel's scalar `__svml_dlog1p_ha_cout_rare_internal`: results, return codes, FP exception flags | 20,031,535 inputs, 0 mismatches |
| `test_log1p8` | Intel's `__svml_log1p8_ha`: all 8 lanes bit-exact | 2,031,536 inputs, 0 mismatches (Intel SDE `-spr`); needs AVX-512F |
| `hwy_test` | every Highway target: error < 1 ulp, special values vs `log1pl`, agreement between targets, special lanes bit-identical to the C callout; with AVX-512: every target bit-identical to the C translation | all checks pass (AVX2 natively; AVX2, AVX3, AVX3_DL, AVX3_SPR under SDE) |
| `make log1p-insns` | arithmetic instruction mix of the compiled vector path vs the assembly | identical |
| `make log1p-xcheck` | Highway on AArch64 NEON/SVE/SVE2 (QEMU) vs x86-64 | bit-identical |

Inputs (`tests/inputs.h`): specials, ±50 ulps around −1, 0, ±0.009765625 (the callout's near-1 path on 1 + x), powers of 2 around 2^52–2^54 and the extremes, ±8 ulps around the `vrcp14pd` thresholds and the boundaries 1 + i/128 of 1 + x at 12 exponents (2^-53 to 2^1023), random values in [−1, 3), small values ±2^-[1,60], random positive bit patterns and random bit patterns. The Highway test driver (`functions/log/tests/log_family_test.h`), the comparison implementations
(`functions/log/tests/extras*`, compiled with `-DFN=log1p`) and the constant generator
(`functions/log/tools/gen_svml_constants.py log1p`) are shared with log. `make log1p-hashes` writes
`arch log1p <target> svml n hash` lines (and `C-AVX512` for the translation when the CPU has AVX-512): all equal.
