## Algorithm (vector path)

pow(x, y) = 2^(y·log2 x), carried in extra precision throughout:

1. **log2 x.** m = `vgetmantpd`(x) ∈ [1/2, 1), E = `vgetexppd`(x) (also exact for denormal x).
   rcp = `vrcp14pd`(m) rounded by `vrndscalepd` to a multiple of 1/32, so rcp = k/32 with k ∈ 33..64.
   The top 5 mantissa bits of rcp index two 32-entry tables (`vpermt2pd` on bits 0–3 plus a blend on
   bit 4): Th + Tl = −log2(rcp), with 1 added for rcp ≥ 1.5, because rcp = k/32 and rcp = k/64 share an
   index; E gets the missing +1 when rcp < 1.5. R = (rcp·m − 1)/2 is exact and |R| < 2^−6.
   log2(1 + 2R) = C1H·R + R·(A0 + A1 R + … + A9 R^9). Here C1H is 2/ln 2 rounded, and A0, A1 are tiny
   corrections for that rounding. The leading part E + Th + C1H·R is summed with error-free steps
   (FMA splits), which gives High + Tll ≈ log2 x to about 2^−100 relative.
2. **y·log2 x** with four **round-toward-zero** operations:
   P = RZ(y·High), Zl = RZ(y·High − P), T = RZ(y·Tll + Zl), S = RZ(P + T), then low = T − (S − P).
3. **2^(S + low).** j and N come from RD(S + 1.5·2^48 + 1023·16) (`{rd-sae}`: floor to a multiple of 1/16,
   with the exponent bias in the low bits). The reduced argument is `vreducepd`(S, 0x41) =
   S − floor(16 S)/16, plus low. 2^z = 2^N · The[j]·(1 + Re·(B1 + … + B6 Re^5) + Tle[j]/The[j]), using
   16-entry tables, and 2^N is built from the shifted exponent bits.
4. **Callout lanes** go to the scalar routine (step 5): x ≤ 0 (incl. −0 and negative denormals; positive
   denormals stay on the vector path), x or y inf/NaN (`vfpclasspd` 0xdf / 0x99), and |S| > 1021.5 or NaN
   (overflow, underflow, denormal results).
5. **Scalar callout**, a different algorithm. It decides whether y is an integer and odd/even (with x86
   32-bit shift semantics), handles the special cases (pow(1, NaN) = pow(NaN, 0) = 1, ±0, ±inf, x = −1,
   x < 0 with non-integer y → NaN with return code 1, pole at x = ±0 with y < 0 → return code 1), then
   computes log2|x| with three reciprocal tables (33/33/129 entries, Rcp1·Rcp2·Rcp3C exact,
   C ≈ 1/ln 2) and Dekker splits, y·log2|x| in double-double, and exp2 with a 128-entry 2^(j/128)
   table. Shortcuts: exponent(log2|x|) + exponent(y) ≥ 2057 → overflow/underflow, ≤ 1984 → ±(1 + tiny).
   Denormal results (N < −1022) are rescaled by 2^200 so that they round once.

## The C translation (`svml/svml_pow_d_ha.c`)

`svml_pow8_ha(__m512d x, __m512d y)` (AVX-512F/DQ, the only function compiled for AVX-512) and
`svml_pow_ha_array(x, y, z, n)` keep the instruction sequence, constants, operand order and rounding mode of
every instruction (`_mm512_*_round_pd` with `RN`/`RZ`/`RD`/SAE). `svml_dpow_ha_cout_rare(px, py, pr)` is the
scalar routine in portable C. Its statement order mirrors the assembly labels (`.LBL_2_*` in comments), it
reads and writes partial words of doubles the way the assembly does through the stack, and it computes the
values that only exist to raise FP flags (x·1 to quiet sNaN, huge², tiny², 1 + tiny, 0/0, x + y in the
pow(1, y) path) through `volatile`, so that results, return codes and exception flags all match.

The instruction mix of the compiled vector path equals the assembly's (`make pow-insns`).
Differences that do not affect results: `vpandq` instead of `vandpd`, and the compiler's choice of
registers and FMA forms.

## Highway version (`hwy/hwy_pow.cc`)

Same algorithm, constants and operation order, with dynamic dispatch. On every target with true FMA
(`HWY_NATIVE_FMA`: AVX2, AVX-512 family, NEON, SVE, SVE2), the AVX-512-only operations are emulated
**exactly**, so the results are bit-identical to Intel's `__svml_pow8_ha`. Targets without FMA
(SSE2/SSSE3/SSE4) use `std::pow`. Callout lanes call the C callout.

| AVX-512 feature | emulation |
|---|---|
| `vgetmantpd` [1/2,1) / `vgetexppd` | exponent and mantissa bits; denormals are scaled by 2^52 first; E converted with the 2^52 magic number |
| `vrcp14pd` + `vrndscalepd` (1/32, RN) | exact, see below: round(32/q)/32 for the mantissa q truncated to 16 fraction bits, corrected near the 32 switch points with a 32-entry table, a branch taken only when some lane is near one |
| `vmulpd {rz-sae}` | RN product p, error e = fma(y, H, −p); p stepped one ulp toward 0 (integer −1 on the bits) when e ≠ 0 has the other sign |
| `vfmsubpd {rz-sae}` (Zl) | plain FMA: y·High − P is exactly representable, so the rounding mode is irrelevant |
| `vfmaddpd {rz-sae}` (T) | RN fma r1, sign of the exact error from ErrFma (Boldo & Muller 2011: TwoProduct, two TwoSums, then sign(RN(g + zz)), because ErrFma's r2 is 0 only if the whole error is 0) |
| `vaddpd {rz-sae}` (S) | TwoSum error sign |
| `vaddpd {rd-sae}` (shifter) | shifter + floor(16 S)/16 (exact) |
| `vreducepd` 0x41 | S − floor(16 S)/16. Per the SDM the subtraction uses the immediate's rounding (down). It is inexact only for −1/32 < S < 0, where a Fast2Sum error picks the lower neighbour. An exact zero becomes −0, as x − x does when rounding down |
| `vpermt2pd` (32- and 16-entry) | `TwoTablesLookupLanes` (vpermt2pd on AVX-512) on chunks of 2N entries, then a recursive tree of `IfNegativeThenElse` on the index bits (no arrays: SVE vectors are sizeless), or one `TableLookupLanes` when a vector holds the table. Tables are `constexpr`, with no gathers |
| `vfpclasspd`, `vcmppd` | compares (`!(x > 0 && x < inf)`, `!(|y| < inf)`, `!(|S| <= 1021.5)`) |

### Why `vrcp14pd` can be emulated exactly

`vrcp14pd`'s bits are implementation-defined in principle, and they are not rounded coarsely enough after
the fact. 1/m comes within 2^−14 of a rounding midpoint (2k+1)/64 for about 1.6 % of all mantissas, and
there rcp14's 2^−14 error decides the rounding. Two facts make it exactly emulatable anyway:

1. Intel's reference implementation (`recip14.c` from *Reference Implementations for IA Approximation
   Instructions*, which the SDM cites as the numerically exact definition) computes the double-precision
   result from the **leading 16 fraction bits** of the input only. It clears the low 36 bits before a
   64-segment linear interpolation, and exact powers of two get exact reciprocals.
2. `tools/gen_rcp14_table.c`, run under Intel SDE (`make pow-rcp14-table RUN="$SDE -spr --"`), checks
   that: for all 65536 prefixes, the lowest, highest, middle and 61 random members give the same `vrcp14pd`
   bits (4.2 M mantissas, 0 violations; m = 1/2 gives exactly 2). It then enumerates the rounded value
   per prefix. That value is non-increasing, with exactly 32 switch points (one per step k → k−1), which
   it writes to `hwy/rcp14_switch.inc`.

The same 32 switch points follow, without SDE, from the integer re-implementation of Intel's `RCP14D`
written for tan (`common/include/hwymath/rcp14_ref.h`, verified there bit-exact against SDE). pow
does not need `vrcp14pd`'s own bits, only their rounding to 1/32, so it uses the switch points rather than
the full piecewise-linear formula.

So rounded rcp = f(prefix), a monotone step function whose steps are known exactly. The emulation computes
t = 32/q (one division; floor and round of t are exact because 32/q is never within 2^−18 of an integer
or half-integer for a 17-bit q). round(t) is correct wherever t is more than 0.0034 from a half-integer:
the switch points are at most 3.5 prefixes from the exact midpoints. Lanes with
|t − floor(t) − 1/2| < 2^−7 instead use kmid = floor(t) and k = kmid + (q < switch[kmid − 32]).
Highway's own `ApproximateReciprocal` is not used: its bits differ between instruction sets.

Caveat: this assumes hardware `vrcp14pd` equals Intel's reference / SDE. The CI's AVX-512 run
(`hwy_test` on real hardware compares every target with the C translation, which uses the real
instruction, on inputs at all switch points ±3 prefixes) checks it.

### Exactness of the error-free steps, and tiny y·log2 x

The sign-of-error tests are exact as long as the error terms do not underflow. Every quantity in the log2
part is a multiple of at least 2^−640: R is a multiple of 2^−59, the tables and constants have ≥ 2^−107
granularity, and R appears at most to the 10th power. If |y| ≥ 2^−381, then ulp(y)·2^−640 ≥ 2^−1074, so
every exact intermediate of the y-part is a multiple of 2^−1074 and the error terms are representable. If
|y| < 2^−381, then |S| < 1075·2^−381 for both the real and the emulated computation. For every |S| < 2^−60
the result is exactly 1.0, whatever S's sign and low bits:

- for S ≥ 0 (or ±0): j = 0, N = 0, so RN(1 + tiny) = 1;
- for S < 0: j = 15, N = −1, Re = 1/16 − 2^−57 exactly, and the constant result is 1.0, as the
  inputs with y down to 2^−1100 confirm under SDE.

Overflow: an infinite RN product steps to ±DBL_MAX like RZ. An overflowing P + T (|P| ≈ DBL_MAX) only
occurs in callout lanes. The emulation does not reproduce it, but |S| > 1021.5 holds either way.

### Verification of the emulated operations

With AVX-512 (or under SDE), `hwy_test` also runs each emulated operation of every target against the
real instruction on dedicated operands. (AVX-512 targets use `vrcp14pd` itself for the rounded reciprocal, so
for that operation the AVX2 row is the one that tests the emulation.) These cover every 16-bit mantissa prefix for the reciprocal;
cancellation, small and large addends, exact products and overflowing products for mul/fma RZ; all
relative scales for add RZ; and multiples of 1/16 ± ulps, tiny values and (−1/16, 0) for reduce. This
matters because end-to-end comparisons are weak evidence here. Replacing an RZ by RN, or dropping the
reciprocal correction, changes the final pow result only rarely: 0 of 300 k end-to-end inputs changed. The
operation tests catch each such mutation immediately.

Inputs (`tests/inputs.h`, 2-D, deterministic and libm-free so that they are identical on every
architecture):

- grids of special values for x (±0, ±inf, NaNs incl. signaling, ±1, 1 ± ulp, denormals, DBL_MAX, …) ×
  y (±0, ±inf, NaNs, small and huge integers of every parity and exponent 0–60, half-integers, denormals, …);
- x < 0 with integer and non-integer y;
- y within ±40 ulps of every threshold of z = y·log2 x for 17 values of x: 1021.5 (vector callout), 1024
  (overflow), −1022, −1032 and −1084 (scalar denormal paths), −1074 and −1075 (underflow), 2^−62 and 2^11
  (scalar shortcuts), and ±1/16 (table boundaries);
- x = 2 with y on every multiple of 1/16 ± 1 ulp; x within 20 ulps of 1 with |y| up to 2^62;
- mantissas at the 32 reciprocal switch points ±3 prefixes (low bits 0, all ones, random) at 8 exponents
  and as denormals;
- m = k/64 boundaries;
- the callout's 3-level table boundaries;
- random pairs: log-uniform x with z uniform in [−1100, 1100], x ∈ (0, 4) with |y| ≤ 100, x near 1 with
  large y, tiny z down to 2^−1100, negative x with integer y, z near the overflow/underflow boundaries, and
  random bit patterns.

Signaling-NaN inputs are left out of the accuracy statistics: pow(sNaN, 0) is NaN in glibc but 1 in SVML
and `powl`.
