# log2 (double precision)

Source studied: [`svml_z0_log2_d_ha.s`](https://github.com/numpy/SVML/blob/9a43e744b15006d63e8d1b57626dfbe6b984f5ee/linux/avx512/svml_z0_log2_d_ha.s)
(AVX-512, high accuracy). Accuracy and speed: [Performance.md](Performance.md). Part of the log family: the
emulation helpers, the `vrcp14pd` analysis, the constant generator and the test driver live in
[functions/log](../log/README.md); this directory has what is specific to log2.

| directory | contents |
|---|---|
| `svml/` | bit-identical C/AVX-512 translation of the assembly, with its constants (`svml_log2_d_ha_constants.inc`, generated by `functions/log/tools/gen_svml_constants.py log2`) |
| `hwy/` | Google Highway version (`hwy_log2.cc`, constants `hwy_log2_constants.inc` generated with `--cxx`) |
| `tests/` | `inputs.h`, `test_rare.c`, `test_log28.c`, `hwy_test.cc` / `hwy_xcheck.cc` (drivers shared with log) |
| `log2_d.h` | declarations of the C translation |
| `function.mk` | build rules and the `log2-*` make targets |

## Algorithm

Vector path: like [log](../log/README.md) (x = 2^E·m, rcp = `vrndscalepd(vrcp14pd(m))` = k/32, exact
R = rcp·m − 1, E + 1 and a −log2(2·rcp) entry when rcp < 0.75), with log2 tables Th + Tl = −log2(rcp) and
log2(1 + R) = c1h·R + R·(c1l + c2 R + … + c10 R⁹), c1h + c1l = 1/ln 2. The sum is formed exactly where it
matters: KT = E + Th (exact), H = KT + c1h·R (one FMA), (c1h·R)_h = H − KT, (c1h·R)_l = c1h·R − (c1h·R)_h
(FMA), result = H + (R·p + (Tl + (c1h·R)_l)). Lanes with x = ±0, ±inf or x < 0 (`vfpclasspd` 0x5e) are
recomputed by the scalar routine; unlike log, NaN and denormal inputs stay in the vector path (NaN
propagates as the quieted input).

The scalar callout `__svml_dlog2_ha_cout_rare_internal` is a separate, libm-style algorithm: by the high word
of x, x = 1 exactly (+0), three polynomial paths for x within ~2^-31 (Q3), ~2^-16 (Q2) and ~2^-6 (Q1) of 1,
with high/low splits (multiplications by 2^32 + 1 and 2^32) for extra precision, and a general path with a 256-entry table of
single-precision reciprocals of the top 8 mantissa bits and {low, high} parts of −log2(rcp); denormals are
scaled by 2^55. Return codes: 1 (x < 0 or −inf: NaN, invalid), 2 (±0: −inf, divide-by-zero).

## The C translation

`svml/svml_log2_d_ha.c`: AVX-512 intrinsics with the assembly's constants (hex-float literals), operation order
and rounding modes; `svml_log28_ha()` (AVX-512F/DQ, the only function compiled for AVX-512),
`svml_log2_ha_array()`, and the scalar callout `svml_dlog2_ha_cout_rare()` in plain C without FMA contraction.
Bit-identical to `__svml_log28_ha` (`test_log28`), same instruction mix (`make log2-insns`).

## Highway version (`hwy/hwy_log2.cc`)

The same algorithm written with Google Highway, run-time dispatch; on every target with true FMA it performs
the same floating-point operations in the same order with the same rounding as `__svml_log28_ha`, and its
results are **bit-identical** to Intel's AVX-512 code: verified under Intel SDE for AVX2, AVX3, AVX3_DL,
AVX3_SPR (`-spr`) and AVX10_2 (`-dmr`) against the C translation, and under QEMU for AArch64 NEON, SVE and
SVE2 at 128/256/512/2048-bit vectors against x86-64 (`make log2-xcheck`). Targets without FMA use `std::log2`.

On every target except the AVX-512 ones, the AVX-512-only operations are emulated exactly by the helpers shared with log (`functions/log/hwy/log_hwy-inl.h`;
details, and the proof that the rounded `vrcp14pd` can be reproduced exactly, in [log's README](../log/README.md)):

| AVX-512 | emulation |
|---|---|
| `vgetmantpd`, `vgetexppd` | integer operations; denormals pre-scaled by 2^52 in a slower variant used only for vectors with a denormal or special lane |
| `vfpclasspd` 0x5e + callout | `!(x >= DBL_MIN && x < inf)` selects the slow variant, then the C callout for `!(x > 0 && x < inf)`; NaN lanes also go to the callout, which returns the same quieted NaN as the vector path |
| masked `vxorpd` | not needed (special lanes are overwritten) |
| `vpermt2pd` (16-entry tables) | `TwoTablesLookupLanes` (one `vpermt2pd` on AVX-512), two/four of them plus selects on 4/2-lane vectors, `TableLookupLanes` on ≥ 16 lanes. No gathers |
| `vrcp14pd` + `vrndscalepd` | exact model: 16 measured thresholds of the rounded reciprocal, a 32-entry `uint32` table and integer operations on the high word of the mantissa |
| masked `vaddpd` (E + 1 if rcp < 0.75) | `MaskedAddOr` |
| `{rn-sae}` | all rounding is round-to-nearest: plain `MulAdd`/`MulSub`/`Add`/`Mul` |

On the AVX-512 targets (`HWYMATH_NATIVE_AVX512`) the shared helpers use Intel's instructions instead (see
[log's README](../log/README.md)): `vgetexppd`/`vgetmantpd` (one vector path, denormals included), `vrcp14pd` +
`vrndscalepd`, the unmasked `vpsrlq $48` index into `vpermt2pd`, and `vfpclasspd $0xdf` (Intel: 0x5e; 0xdf also
sends NaN lanes to the callout, as on the other targets). AVX3 loop: 30 vector/mask instructions besides loads,
stores and register moves (39 with the emulations; Intel's main path: 31 including `kmovw` and the
`vxorpd` that is not needed here).

Deviations: none in the results. The vector code may raise FP flags where the `{sae}` assembly does not;
special lanes go through the same C callout, which raises the documented flags. The C callout returns NaNs
with x86's default-NaN sign on every architecture (`copysign(..., -1.0)`, a no-op on x86), so that AArch64
results are identical.

## Tests (`make log2-test`, `make log2-avx512-test`)

| test | compares with | result |
|---|---|---|
| `test_rare` | Intel's scalar `__svml_dlog2_ha_cout_rare_internal`: results, return codes, FP exception flags | 20,029,320 inputs, 0 mismatches |
| `test_log28` | Intel's `__svml_log28_ha`: all 8 lanes bit-exact | 2,029,320 inputs, 0 mismatches (Intel SDE `-spr`); needs AVX-512F/DQ |
| `hwy_test` | every Highway target: error < 1 ulp, special values vs `log2l`, agreement between targets, special lanes bit-identical to the C callout; with AVX-512: every target bit-identical to the C translation | all checks pass (AVX2 natively; AVX2, AVX3, AVX3_DL, AVX3_SPR under SDE) |
| `make log2-insns` | arithmetic instruction mix of the compiled vector path vs the assembly | identical |
| `make log2-xcheck` | Highway on AArch64 NEON/SVE/SVE2 (QEMU) vs x86-64 | bit-identical |

Inputs: the same file as log's (`tests/inputs.h`), which includes the windows of this callout around 1 (high words 0x3fef8000, 0x3feffff0, 0x3ff00008, 0x3ff05000 and 1 ± 2^-31, ± 2^-32) and random values 1 ± 2^-[1,60]. The Highway test driver (`functions/log/tests/log_family_test.h`), the comparison implementations
(`functions/log/tests/extras*`, compiled with `-DFN=log2`) and the constant generator
(`functions/log/tools/gen_svml_constants.py log2`) are shared with log. `make log2-hashes` writes
`arch log2 <target> svml n hash` lines (and `C-AVX512` for the translation when the CPU has AVX-512): all equal.
