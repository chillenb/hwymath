## Algorithm

With ax = |x|, ay = |y|, the vector path first finds the interval of |y/x| without dividing, from four
products and compares: ax·7/16 < ay, ax·11/16 < ay, ax·19/16 < ay, ax·39/16 < ay. In each interval
atan(ay/ax) = atan(c) + atan(a/b) with |a/b| ≤ 7/16:

| \|y/x\| | a | b | atan(c) |
|---|---|---|---|
| < 7/16 | ay | ax | 0 |
| < 11/16 | ay − ax/2 | ax + ay/2 | atan(1/2) |
| < 19/16 | ay − ax | ax + ay | π/4 |
| < 39/16 | ay − 1.5 ax | ax + 1.5 ay | atan(3/2) |
| otherwise | −ax | ay | π/2 |

a and b are single FMAs; atan(c) is a double-double (Hi + Lo) chosen by masked blends. The quotient is
a double-double R + Rlo: r0 = `vrcp14pd`(b), two Newton steps r1 = r0 + r0(1 − b r0),
r2 = r1 + r1(1 − b r1), R = RN(r2·a), Rlo = r2·(a − R b) (FMA). atan(a/b) ≈ R + R·R²·P(R²) with P of
degree 11, evaluated as two Estrin-like halves in R⁴. The sum is formed as
((Rlo + atan(c)_lo [+ π_lo·sign(x) if x < 0]) + R·P') + R, then + atan(c)_hi; the result gets the sign of
x, π is added for x < 0, and the sign of y is or-ed in.

Lanes where x or y has a high word outside [0x00300000, 0x7e000000), i.e. |v| < 2^-1020, |v| ≥ 2^993,
±inf or NaN, are special (the assembly checks this with 32-bit `vpsubd`/`vpcmpgtd` on the high words;
exhaustively verified to be equivalent to `hi < 0x00300000 || hi >= 0x7e000000`). If any lane is
special, a vector branch computes the lanes with a zero argument and no NaN directly (±0, ±π/2, ±π, from
the rule "π/2 unless |y| < |x|, 0 if both are zero, + π if x has its sign bit set"), and the remaining
special lanes are recomputed by the scalar routine `__svml_datan2_ha_cout_rare_internal` (a complete
scalar atan2 with its own table, scaling of extreme exponents and the IEEE special cases; it always
returns 0). The vector path's π_lo constant (`0x3ca1a64000000000`) is a truncated value, not the low part
of π; this is kept (its effect is ~10^-5 ulp).

## The C translation

`svml/svml_atan2_d_ha.c` keeps the algorithm, the constants (bit-exact hex-float literals), the operation
order and every instruction's rounding mode, so its results are bit-identical to Intel's (`test_atan28`).

- `svml_atan28_ha(y, x)`: the vector routine (AVX-512F at run time); `svml_atan2_ha_array(y, x, r, n)`.
- `svml_atan28_ha_portable(y, x)`: the same with `vrcp14pd` replaced by the Highway version's portable
  approximation (below); the reference for the Highway targets.
- `svml_datan2_ha_cout_rare(&y, &x, &r)`: the scalar callout, plain portable C generated by `asm2c.py`
  (one C statement per instruction on a small machine model; see that script and
  `functions/asin/svml/asm_model.h`); bit-identical results, return codes and FP exception flags
  (`test_rare`).
- `svml_atan2_ha_zero_args(y, x)`: the vector code's zero-argument branch for one lane, in scalar C (used
  by the Highway version).

Differences from the assembly that do not affect results: the bitwise operations use the integer forms
(`vpandq`/`vpxorq`, AVX-512F) instead of `vandpd`/`vxorpd` (AVX-512DQ); compiler barriers keep the
compiler from merging the sign xors into `vpternlogq` and 0.0 is loaded from memory (not a `vxorpd`
zeroing idiom), so that `make atan2-insns` compares equal instruction mixes; register allocation and FMA
forms (132/213/231) are the compiler's.

## Highway version (`hwy/`)

`hwy/hwy_atan2.cc` ports the same algorithm with [Google Highway](https://github.com/google/highway) 1.4
and run-time dispatch:

| AVX-512 feature | emulation |
|---|---|
| `{rn-sae}` arithmetic, FMAs (`vfmadd`, `vfnmadd`) | `Mul`/`Add`/`MulAdd`/`NegMulAdd` (round-to-nearest; the operations are the same, so the results are) |
| masked operations, `vblendmpd`, merge-masked FMAs | `IfThenElse`, `IfThenZeroElse` |
| `vcmppd` (LT_OQ) | `Lt` (the vector path never sees NaN: those lanes are special) |
| high-word range check (`vpsrlq`, `vpmovqd`, `vpsubd`, `vpcmpgtd`/`vpcmpeqd`) | `|v| >= 2^-1020 && |v| < 2^993` on doubles (exactly equivalent, NaN included) |
| zero-argument branch, callout | scalar, per special lane: `svml_atan2_ha_zero_args` or the C callout (out of line, `cold`) |
| `vrcp14pd` | **not reproducible**: see below |

`vrcp14pd`'s result bits are implementation-defined. Under Intel SDE they are a function of the top 16
mantissa bits of the input and have at most 16 significant bits; reproducing them would need a table of
2^16 entries (gathers, which this project avoids). The final result depends on them: r2 is not always the
correctly rounded 1/b (the rounding error of r1 carries over), and R = RN(r2·a) then occasionally
differs. The Highway version therefore uses **trunc16(RN(1/b))** (division, mantissa truncated to 16
bits: same format, relative error < 2^-15.9 instead of 2^-14) on every FMA target. Consequences:

- the results are bit-identical on every FMA target and machine (x86-64 AVX2/AVX-512, AArch64
  NEON/SVE/SVE2 checked under QEMU, and by construction RVV: only IEEE operations), and equal to
  `svml_atan28_ha_portable`;
- they differ from Intel's in **6 of 2,003,640** test inputs (0.0003 %); the error statistics are
  unchanged (max 0.786 ulp on the 2M test set, as Intel's);
- `hwy_atan2_native_array` uses `vrcp14pd` itself on AVX-512 targets (`ApproximateReciprocal`): it is
  bit-identical to Intel's code on the same CPU (verified under SDE), which also proves that all other
  operations are emulated exactly. On other targets it is the same as `hwy_atan2_array`.

Targets without FMA (SSE2/SSSE3/SSE4) use `std::atan2`.

## Tests (`make atan2-test`, `make atan2-avx512-test`)

| test | compares with | result |
|---|---|---|
| `test_rare` | Intel's scalar `__svml_datan2_ha_cout_rare_internal`: results, return codes, FP exception flags | 2,003,640 input pairs, 0 mismatches (default run: 20M) |
| `test_atan28` | Intel's `__svml_atan28_ha`, all 8 lanes bit-exact | 2,003,640 input pairs, 0 mismatches (Intel SDE `-spr`) |
| `hwy_test` | every Highway target: error bound (max ≤ 0.9 ulp, none > 1 ulp), special inputs (zero arguments vs glibc's exact results, other special lanes vs the callout), identical results on all FMA targets; with AVX-512: bit-identity with `svml_atan28_ha_portable` (all FMA targets) and of the native variant with `svml_atan28_ha` | all checks pass (AVX3_SPR, AVX3_DL, AVX3, AVX2 under SDE; AVX2 natively) |
| `make atan2-insns` | arithmetic instruction mix of the compiled vector path vs the assembly | identical |
| `make atan2-xcheck` (`pixi run -e cross`) | Highway NEON, SVE and SVE2 under QEMU (SVE at 128, 256, 512, 1024 and 2048 bits, i.e. 2 to 32 lanes) vs x86-64 AVX2: inputs and results bit for bit (`functions/asin/tools/xcheck_invtrig.sh`) | identical on all 11 AArch64 configurations (200,000 random inputs plus the edge cases) |

Inputs (`tests/inputs.h`, pairs (y, x)): all 28 × 28 combinations of special values (±0, ±inf, NaNs with
payloads, ±denormals, ±DBL_MIN, the exponent limits 2^-1020 and 2^993 with neighbours, ±DBL_MAX, ...);
y = x·t ± 20 ulps for the interval thresholds t = 7/16, 11/16, 19/16, 39/16 at several magnitudes and all
sign combinations; magnitudes around 2^-1020 and 2^993 in ulp and high-word steps against ordinary
values; random pairs (uniform in [-2, 2]², random ratios in [2^-8, 2^8], log-uniform magnitudes over the
whole exponent range, arbitrary bit patterns). `make atan2-hashes` writes the result hashes (`svml-c intel`,
`svml-c port` with AVX-512, and `port`/`native` per Highway target) for the cross-machine check.
